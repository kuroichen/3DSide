# ステージ進行の仕組み(ランタイム)

ステージ内で「エリアを切り替える・チェックポイントを踏む・ゴールする」がどう動くかの全体像。
エディタでの作り方は [ステージ作成パイプライン.md](ステージ作成パイプライン.md) を参照。

## ワールド画面からのステージロード

`WorldView.OnClickAsObservable()` は `StageId` を通知する。`stageButtons` は `StageId` の定義順に対応し、現在の5ボタンは先頭から `Stage1`〜`Stage5`。ループ内で各ボタンのIDをローカル変数に保持し、クリック時にループ終了後のインデックスを参照しないようにする。

`WorldPresenter` は選択されたIDから `StageRequest(WorldId.World1, stageId)` を作り、`LifetimeScope.Enqueue` で登録した状態で `StageScene` をロードする。`StageLifetimeScope` で生成される `StagePresenter` がリクエストを受け取り、`StageLoader` が `{WorldId}_{StageId}`（例: `World1_Stage2`）をAdditiveロードする。実ステージも共有Scene Listへの登録が必要。現在 `World1_Stage1` と `World1_Stage2` が登録済みで、Stage3以降はシーン作成・登録後に利用できる。

## 登場人物

```
StageFlowManager      … 進行の指揮者。イベントを受けて遷移・フェード・リスポーンを実行
StageDefinition       … ステージ1面の定義。全AreaTriggerのイベントを束ねて1本のObservableに
StageArea             … エリア(contentsRootのON/OFFで有効化・無効化)
AreaTrigger           … 透明な箱。プレイヤーが触れるとeventInfoを発火
AreaEventInfo(基底)   … トリガーに配線する「何が起きるか」のデータ
SplineAnchor          … 「どのSplineのどの位置か」を指す地点マーカー(スポーン・遷移先)
```

## イベントの流れ(パイプライン)

```
プレイヤーがAreaTriggerの箱に進入
  → OnTriggerEnter(Tagが"Player"かで判定)
    → AreaTrigger.OnEnteredObservable が eventInfo を発火
      → StageDefinition が全トリガー分を束ねて OnAreaEventObservable に流す
        → StageFlowManager.HandleAreaEvent が型でswitchして処理
```

イベントは `AreaEventInfo` の**派生型で意味が決まる**(C#のパターンマッチングで分岐):

| 型 | 内容 | 現在の処理 |
|---|---|---|
| `AreaTransitionInfo` | 遷移先エリア + 遷移先SplineAnchor | フェード→エリア切替→プレイヤー移動→フェード解除 |
| `CheckPointInfo` | 復帰地点(SplineAnchor) | `PlayerManager.SetRespawnPoint` を更新 |
| `GoalInfo` | GoalType(Normal/Secret/Fake) | **未実装**(Debug.Logのみ。Phase 1対応予定) |
| `StageExitInfo` | ステージ退出 | **未実装**(同上) |

新しいイベント(例: ボス戦開始、演出トリガー)を足すには、`AreaEventInfo` の派生クラスを作って
`HandleAreaEvent` のswitchに1ケース足すだけ。トリガー配置側は共通の `AreaTrigger` を使い回せる。

## エリア切り替えの実際(ChangeAreaAsync)

```
① フェードアウト(暗転)
② 遷移先エリアの contentsRoot をON
③ プレイヤーを遷移先SplineAnchorへ移動
   (CharacterControllerを一旦disableしてテレポート + SetSplineでレールも切替)
④ 元エリアの contentsRoot をOFF
⑤ フェードイン
```

- エリア=「GameObjectのON/OFF単位」。ロードではなく**同一シーン内の切り替え**なので高速
- ONにしてからプレイヤーを移す順序が重要(OFFの地面に着地させない)
- `isChangingArea` フラグで多重遷移を防止

## リスポーンの流れ

```
死亡: HPが0 → OnDeadObservable → StageFlowManagerがフェードアウト開始
      死亡アニメ終了(AnimationEventのOnDied) → OnDiedObservable
  → フェードアウト完了を待ってから PlayerManager.TryRespawn
      残機あり: 残機-1 → 現在のRespawnPoint(最後のチェックポイント)にSpawn → フェードイン
      残機なし: OnGameOver発火(※現状購読者なし=ソフトロック。Phase 1で対応)
```

- 「死亡通知(Dead)」と「死亡アニメ終了(Died)」が別イベントなのがポイント。演出が終わるまでリスポーンを遅らせるためにUniTaskCompletionSourceでフェードと合流させている
- リスポーンは**プレイヤーを作り直す**(Delete→Instantiate)。状態のリセット漏れが起きない方式

## 注意点・落とし穴

- **AreaTriggerはTag("Player")、戦闘系はLayerで判定している**。フィルタ方式が2系統あるので、プレハブのTag/Layer両方が正しく設定されている必要がある(片方だけ設定してトリガーが無反応、が起きやすい)
- `AreaEventInfo` はMonoBehaviour。トリガーの箱と同じGameObjectか近くに置いてInspectorで配線する
- SplineAnchorは位置だけでなく**どのSplineに乗せるか**も持つ。遷移先でレールが切り替わっていない場合はAnchorの`SplineContainer`設定を疑う
