# ステージ進行の仕組み(ランタイム)

ステージ内で「ロードする・エリアを切り替える・死んで復帰する」がどう動くかの全体像。
エディタでの作り方は [ステージ作成パイプライン.md](ステージ作成パイプライン.md) を参照。

> 2026-10 にVContainer + MVP構成へ移行した。旧 `StageFlowManager` / `PlayerManager` / `CheckPointInfo` は削除済み。

## ワールド画面からのステージロード

```
WorldView(ステージボタン)── StageId ──▶ WorldPresenter
   ├ ScreenTransition.FadeOut()(暗転したままStageSceneへ。ScreenTransitionは常駐なので暗転が続く)
   └ LifetimeScope.Enqueue で StageRequest(WorldId, StageId) を登録して StageScene をロード
        ▼
StageLifetimeScope(StageScene)が StagePresenter などを生成し、StageRequest を注入
        ▼
StagePresenter.LoadStageAsync
   └ StageLoader が "{WorldId}_{StageId}"(例: World1_Stage1)を Additive ロード
       ├ ステージSceneの確認用カメラを無効化(実行時のカメラはStageSceneの1台だけ)
       ├ ルートに InjectGameObject(StageView / AreaTrigger / PlayerView などへの注入)
       └ StageDefinition を探して返す
```

- `WorldView.OnClickAsObservable()` は `StageId` を通知する。`stageButtons` は `StageId` の定義順に対応(先頭から `Stage1`〜`Stage5`)。ループ内で各ボタンのIDをローカル変数に保持し、ループ終了後のインデックスを参照しないようにする
- 実ステージは共有Scene Listへの登録が必要。現在 `World1_Stage1` と `World1_Stage2` が登録済み

## 登場人物

```
【StageScene(ステージをまたいで生きる)】
StageLifetimeScope  … DI登録。PlayerEntity(初期値はCharacterStatus)、各Presenter/Model/EventBus
StagePresenter      … ステージの進行(ロード・エリア切替・リスポーン指示)
StageModel          … 今いるエリアのidと復帰地点(StageEntity)
PlayerPresenter     … プレイヤーの生成・作り直し・HP/残機の判断の窓口・死亡時の暗転
StageHUDPresenter   … PlayerModelのHP/残機をStageHUDViewへ
SplineFollowCamera  … 実行時の唯一のカメラ

【個別ステージScene(World1_StageX。Additiveロード)】
StageDefinition     … シーンの入口(名札)。初期エリアとStageViewの在り処
StageView           … 統括View。エリア操作・トリガー集約・敵のリセットの唯一の窓口
StageArea ×N        … パーツView。areaId・contentsRoot・開始地点・敵の出現地点
AreaTrigger ×N      … 透明な箱。プレイヤーが触れると eventInfo を通知
AreaEventInfo(派生) … トリガーに配線する「何が起きるか」のデータ
EnemySpawnPoint ×N  … 敵の出現地点(SplineAnchor + プレハブ)。実体は実行時に生成
```

### 責務の線引き

- **Definitionは「読むもの」、Viewは「操作するもの」**。StagePresenterはロード直後にDefinitionから初期エリアとViewを受け取り、以降はViewとだけ話す
- **2段のView**: StagePresenter → StageView(統括)→ StageArea / AreaTrigger(パーツ)。Presenterはパーツに直接触らず、**エリアidで** StageViewに指示する。パーツは外(EventBusや他エリア)を知らない
- 例外: `StageDefinition.initialArea` と `AreaTransitionInfo.destinationArea` はInspector配線ミス防止のため `StageArea` を参照で持つが、使う側は `AreaId` だけを読む
- StageViewはAreaTriggerを束ねて `StageEventBus.PublishAreaTrigger` に流す(`Construct` で購読する。`Start` だと注入前に走る可能性がある)。Presenterはコンストラクタで常駐のEventBusを購読するので、動的にロードされるViewの寿命を気にしなくてよい

## イベントの流れ(エリアイベント)

```
プレイヤーがAreaTriggerの箱に進入(Tagが"Player"かで判定)
  → AreaTrigger.OnEnteredObservable が eventInfo を発火
    → StageView が全トリガー分をMergeして StageEventBus.PublishAreaTrigger
      → StagePresenter.HandleAreaEvent が型で分岐
```

| 型 | 内容 | 現在の処理 |
|---|---|---|
| `AreaTransitionInfo` | 遷移先エリア + 遷移先の出現地点(SplineAnchor) | エリア切替 → プレイヤー移動(**暗転は未実装**) |
| `GoalInfo` | GoalType(Normal/Secret/Fake) | **未実装**(処理なし) |
| `StageExitInfo` | ステージ退出 | **未実装**(処理なし) |

## エリア切り替え(ChangeArea)

```
① StageModel.TryChangeArea(id, 出現地点)  … 同じエリア・不正なidは弾く。前のエリアidは事前に控える
② StageView.SetAreaActive(遷移先, true)
③ StageEventBus.PublishPrepared(出現地点) → PlayerPresenter が PlaceAt で移動(居なければ生成)
④ StageView.SetAreaActive(前のエリア, false)
```

- エリア=「contentsRootのON/OFF単位」。ロードではなく**同一シーン内の切り替え**なので高速
- ONにしてからプレイヤーを移す順序が重要(OFFの地面に着地させない)
- 敵はcontentsRoot配下に生成されるので、エリアのON/OFFに自動で追従する
- 初期エリアも同じ `ChangeArea` を通る(Prepared → プレイヤー生成 → Spawned → 明転)

### 出現地点と復帰地点(チェックポイント)

- **出現地点は「どこから入ったか」で決まる**ので、遷移ごとに `AreaTransitionInfo.destinationPoint` で指定する(エリアA2→B1ならB1、B1→A2ならA2)。`StageArea.startPoint` はステージ開始時の1点だけ
- **復帰地点=最後に入ったエリアの入口**。`StageEntity.SpawnPoint` にエリア切替のたびに入る。エリア途中の中間地点(専用のチェックポイント)は設けない方針

## 死亡 → リスポーン

```
被弾/即死 → PlayerModel がHP0と判定 → PlayerView.Die() + PlayerEventBus.PublishDead()
死亡アニメ終了(アニメイベント OnDied)→ PlayerEventBus.DeathAnimationFinished
  → PlayerPresenter.HandleDeathAsync
      ├ await ScreenTransition.FadeOut()   ← 暗転しきってから次へ(作り直しを見せない)
      └ PlayerModel.TryConsumeLife()
          ├ 成功 → PlayerEventBus.LifeConsumed
          │    → StagePresenter: StageView.ResetEnemies() + StageEventBus.PublishRespawnRequest(StageEntity.SpawnPoint)
          │      → PlayerPresenter.RespawnPlayer(Destroy → Create。HPは PlayerModel.ResetHp)
          │        → PlayerView.Start → Spawned → PlayerPresenter が FadeIn
          └ 失敗 → PlayerEventBus.LivesDepleted(**購読者なし=暗転のまま。ゲームオーバー未実装**)
```

- 「死んだ(Dead)」と「死亡アニメ終了(DeathAnimationFinished)」は別イベント。演出が終わるまでリスポーンを遅らせる
- リスポーンは**プレイヤーを作り直す**(Destroy→Instantiate)。PlayerCharacterの内部状態(ステート・ノックバック等)のリセット漏れが起きない
- 敵は消して出し直すだけで初期状態に戻る(Spawner方式。[ステージ作成パイプライン](ステージ作成パイプライン.md))
- HP・残機・被弾の判断は [キャラクターステータスの仕組み](キャラクターステータスの仕組み.md) の「プレイヤーのHP」を参照

## 暗転の担当

| 場面 | 暗転 | 明転 |
|---|---|---|
| ステージ選択 → 開始 | WorldPresenter | PlayerPresenter(Spawned) |
| 死亡 → リスポーン | PlayerPresenter(死亡アニメ後) | PlayerPresenter(Spawned) |
| エリア遷移 | **未実装** | **未実装** |

エリア遷移の暗転を入れるときは、StagePresenterで「FadeOut → ChangeArea → FadeIn」(遷移中は次のトリガーを受け付けない)を行う予定。複数のPresenterが同じScreenTransitionを操作するため、暗転が重なる場面(遷移中の死亡など)が問題になったら担当の集約を検討する。

## 注意点・落とし穴

- **AreaTriggerはTag("Player")、戦闘系はLayerで判定している**。フィルタ方式が2系統あるので、プレハブのTag/Layer両方が正しく設定されている必要がある
- **購読してから通知を出す**。「通知を出してから結果を待つ」処理を書くときは、待つ側の購読(`.First().ToUniTask()` など)を通知の前に開始する。逆にすると取りこぼして止まる
- **Subjectの `OnNext` は購読者をその場で同期実行する**。「通知 → 作り直し」が同じフレームで一気に進むので、暗転を挟むなら通知の前に `await FadeOut()` する
- **空・フォグ・環境光(RenderSettings)はアクティブシーンの設定が使われる**。今のアクティブシーンはStageSceneなので、ステージSceneのテーマ設定(`ApplyEnvironment`)は反映されない。反映するなら `SceneManager.SetActiveScene` が必要だが、そうするとプレイヤーの生成先もステージSceneになる点に注意
- `AreaEventInfo` はMonoBehaviour。トリガーの箱と同じGameObjectか近くに置いてInspectorで配線する(Creatorが配線する)
- SplineAnchorは位置だけでなく**どのSplineに乗せるか**も持つ。遷移先でレールが切り替わっていない場合はAnchorの`SplineContainer`設定を疑う
