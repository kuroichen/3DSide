# Spline移動の仕組み(入門)

キャラクターがどうやってレールの上を動いているかを、コードを読む前の入門として説明する。
罠や調整値の詳細は [レール移動系ナレッジ.md](レール移動系ナレッジ.md) を参照。

## 一言でいうと

> キャラの位置は「どのレールの・始点から何メートル地点か(railZ)」という**たった1つの数値**で決まる。
> 横入力はこの数値を増減させているだけ。高さ(y)だけは重力・ジャンプの物理で動く。

`transform.position` を直接動かすのではなく、「レール上の住所」を動かして、そこからワールド座標を逆算する。
これが大原則「x/zはレールが決める。yは物理が決める」の意味。

## 3層構造

```
PlayerCharacter / EnemyCharacter   … 「どっちに動きたいか」を決める(入力・AI・ステート)
        ↓ GetInput() で -1〜+1 を返す
CharacterMover                       … 物理(重力・ジャンプ・接地・壁)とCharacterControllerへの適用
        ↓
SplineMover                          … railZの管理。レール座標⇔ワールド座標の変換、レール乗り換え
```

- 新しい「レール上を動くもの」を作るときは `SplineMover`(物理不要)か `CharacterMover`(重力あり)を継承して `GetInput()` を実装するだけ
- 例: `EnemyCharacter.GetInput()` は「端に着いたら向きを反転して±1を返す」だけで巡回が成立している

## 毎フレームの流れ

```
① 入力を取る            input = GetInput()                       (-1〜+1)
② railZを進める         railZ += (input + 外力) × Speed × dt
③ 端でクランプ          レール範囲+余白に収める(空中は余白拡大)
④ ワールド座標に変換     Position = rail.Local2World(0, 0, railZ)  ← XZの目標位置
⑤ 重力・ジャンプ計算     verticalVelocity を更新                    ← Yの移動量
⑥ CCで移動             CharacterController.Move(目標との差分XZ + Y)
⑦ レール乗り換え判定     全レールに「今の位置、担当できる?」と問い合わせ
```

ポイントは⑥: CCへ渡すのは**「目標位置と現在位置の差分」**であって、絶対座標へのワープではない。
差分には上限速度(`railCorrectionSpeed` 15m/s)を掛けるので、レール乗り換えで目標が飛んでも
ヌルッと寄っていく(瞬間ワープしない)。

## 壁と端の扱い

- **壁**: 移動前にCapsuleCastで先読みし(Terrain/Gimmickレイヤーのみ)、当たるなら `RevertT()` でrailZを1フレーム前に戻す。「進めない」をレール座標側で表現する
- **端**: レールの端でrailZはクランプされるが、余白(接地中1m/空中5m)まではみ出せる。余白を超えるとそのレールは「担当」を名乗れなくなり、近くの別レールが拾う=**乗り換え**。だからゲートなしでジャンプによるルート分岐ができる(詳細は レール移動系ナレッジ §2〜3)

## よくある誤解

- ❌「Splineのtを進めて `EvaluatePosition(t)` に立たせている」
  → ✅ tではなく**実距離(railZ)**で管理する。tは曲率で速度が揺れるため([learning/03参照](../learning/03_UnitySplinesの使い方.md))
- ❌「ジャンプ中は物理で放物線を描いている」
  → ✅ 放物線に見えるのは「railZが進み続ける(横) + verticalVelocityの重力(縦)」の合成。だから端でrailZが止まると横移動も止まる
- ❌「レール乗り換えはトリガーで検知している」
  → ✅ 毎フレーム全レールへの問い合わせ(`RailManager.World2Local`)で、位置だけから自動判定している
