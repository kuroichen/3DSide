# 画面フェードの仕組み

`ScreenTransition` の解説。エリア遷移・リスポーン・ステージ開始の暗転はすべてこれ1つで行う。

## 構成

- 実体は**全画面の黒いImage 1枚**。アルファ値だけを動かす
- RootLifetimeScopeプレハブ内の常駐Canvas(Screen Space - Overlay)に載っている([RootLifetimeScope常駐パターン](../learning/08_RootLifetimeScope常駐パターン.md))
- RootLifetimeScopeに `RegisterComponent` されており、使う側はDIで受け取る(シングルトンではない)

## API

| メソッド | 動作 |
|---|---|
| `FadeOut()` | 暗転する(async・完了を待てる) |
| `FadeIn()` | 暗転解除(同上) |
| `FadeOutIn()` | 暗転→解除を連続実行 |
| `ShowBlackImmediately()` | フェードなしで即座に真っ黒へ |

すべてUniTaskなので、`await transition.FadeOut();` の後に続けて書いた処理は暗転完了後に実行される。
「暗転してから切り替えて、明ける」が直列に書けるのが肝([UniTaskの使い方](../learning/07_UniTaskの使い方.md))。

## 設計上のポイント

### フェード中は入力もブロックする

`Image.raycastTarget` をフェード開始でtrue、明け切ったらfalseにしている。
暗転中にボタンが押せてしまう事故(二重遷移など)を、見た目と同じ部品で防ぐ。

### unscaledDeltaTimeで進める

`Time.timeScale = 0`(ポーズ)中でもフェードが完了するよう、補間は `unscaledDeltaTime`。
将来ポーズメニューを実装したとき「ポーズ→タイトルへ」のフェードが止まらない。

### 「通常時は透明」が常駐側との契約

RootLifetimeScopeはどのシーンでも存在するため、初期状態は透明で待機する(`Start Black` はOFF)。
「ステージは暗転から始めたい」はシーン側の都合なので、`StagePresenter` が開始時に
`ShowBlackImmediately()` を呼んでから `FadeIn()` する、という役割分担になっている。
テストシーンなど何もしないシーンでは画面を覆わない。

### 演出の担当

`ScreenTransition` はRootLifetimeScopeに登録された常駐サービスで、各PresenterがDIで受け取る(LifetimeScopeのあるシーンでは必ず存在する)。暗転・明転をどのPresenterが行うかは [ステージ進行の仕組み](ステージ進行の仕組み.md) の「暗転の担当」を参照。

## 使う側の実例

- エリア遷移: FadeOut → エリア切替+プレイヤー移動 → FadeIn([ステージ進行](ステージ進行の仕組み.md))
- リスポーン: 死亡通知でFadeOut開始、死亡アニメ完了と合流してからリスポーン → FadeIn
