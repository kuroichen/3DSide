# キャラクターステータスの仕組み

HP・速度・攻撃力などの数値がどこで定義され、どう流れるかの解説。

## 二段構え: 定義(SO)と実体(Runtime)

```
CharacterStatus (ScriptableObject)      … マスターデータ。アセットとして編集する定義値
        ↓ Awake時にコンストラクタでコピー
CharacterStatusRuntime (純粋C#クラス)   … 実行中の状態。現在HPの増減はこちらだけ
```

> **プレイヤーのHPは例外**(2026-10-12〜): プレイヤーの現在HPは `PlayerModel`(`PlayerEntity`)が持つ。下の「プレイヤーのHP」を参照。以降の `CharacterStatusRuntime` のHP周りの説明は**敵**の話。プレイヤーの `CharacterStatusRuntime` は速度・ジャンプ力・攻撃力の参照にだけ使われ、HPは減らない。

```csharp
// CharacterMover.Awake
this.runtimeStatus = new CharacterStatusRuntime(this.defaultStatus);
```

### なぜ直接ScriptableObjectを書き換えないのか

1. **SOはアセット共有**: 同じ `CharacterStatus` を参照する敵が10体いたら、1体のHPを減らすと全員減る
2. **Editorでは変更が永続化する**: Play中にSOのフィールドを書き換えると、Play終了後もアセットに残る(初期HP3のはずが2で保存される事故)
3. リスポーンで作り直せば初期値に戻したい → 実体をnewし直すだけで済む

**「SOは読み取り専用、実行中の値はRuntimeクラスへコピー」はUnity全般の定石**なので、新しいステータス項目もこの経路に乗せること。

## インターフェース分離 — 相手に必要な面だけ見せる

`CharacterStatusRuntime` は `ILife`(HP系)と `IAttack`(攻撃力)を実装し、
キャラクター本体は `ICharacterProperties` 経由でそれを公開する:

```csharp
public interface ILife    { /* CurrentHp, TakeDamage, Heal, OnDeadObservable... */ }
public interface IAttack  { int Attack { get; } }

// CharacterMover
public IAttack AttackProperty => this.runtimeStatus;
public ILife LifeProperty => this.runtimeStatus;
```

- 回復アイテムは `LifeProperty.Heal` しか触れない(攻撃力を書き換える事故が型で防がれる)
- UIは `LifeProperty` の購読だけでHPバーが作れる
- 攻撃処理は相手の `IDamageable` だけ見る([当たり判定](当たり判定の仕組み.md))

## HP変化のイベントは粒度別に4本ある

```csharp
OnLifeChangedObservable()  // 増減問わず、変化後のHP値       → UI表示向け
OnSubLifeObservable()      // 減った時だけ、減少量           → 被弾リアクション向け
OnAddLifeObservable()      // 増えた時だけ、実際の回復量      → 回復エフェクト向け
OnDeadObservable()         // HPが0になった瞬間              → 死亡処理向け
```

購読側が `Where` で判別する手間をなくすため、発行側で分けてある。
例: `EnemyCharacter` はSubLifeでDamageステートへ、DeadでDeadステートへ遷移する。

- `TakeDamage` はHPを0未満にしない(Mathf.Max)。Deadは**0になったちょうどその時**に1回だけ発火
- `Heal` は最大HPを超えない。イベントに流れるのは**実際に回復した量**(満タン時は0)

## 現在の定義値の場所

- アセット: `Assets/Data/` 配下(`Rail/CharacterStatus` メニューで作成)
- 項目: `hp` / `speed` / `jumpForce` / `attack` の4つ
- ⚠ `jumpForce` は身長スケーリング(`scaleJumpByHeight`)有効時は使われない([レール移動系ナレッジ §4](レール移動系ナレッジ.md))

## プレイヤーのHP(PlayerModelが本体)

MVPへの移行で、プレイヤーのHP計算と死亡判定は `PlayerModel` に移した。`PlayerCharacter`(体)は「攻撃を受けた」と報告するだけで、HPを計算しない。

```
PlayerCharacter.TakeDamage ──OnAttackReceived(DamageInfo)──▶ PlayerView ──▶ PlayerEventBus
                                                                              │
PlayerPresenter.ApplyDamage ── PlayerModel.Damage(量) ──▶ DamageResult ◀─────┘
   ├ Ignored … 何もしない(死亡済み・ダメージ0。今後の無敵時間もここ)
   ├ Damaged … PlayerView.PlayHitReaction(attacker)(ノックバック+ダメージステート)
   └ Died    … PlayerView.Die() + PlayerEventBus.PublishDead()
```

- 通知名は「出した時点で確定している事実」に合わせる。`AttackReceived` はHPに反映される**前**(Modelが受け付けない場合がある)。HPが減ったことはModelの `OnHpChangedObservable` で分かる
- 「死んだ(Dead)」はModelの判定を受けてPresenterが出す。「死亡アニメ終了(DeathAnimationFinished)」は体のアニメイベント(`OnDied`)由来なのでPlayerCharacterに残る
- プレイヤーは生成し直すたびに `PlayerModel.ResetHp()` で最大HPに戻す
- HUD(`StageHUDPresenter`)は `PlayerModel` のHP・残機の変化だけを見る。購読時に `StartWith(現在値)` で初期表示する
- 未移行: 落下死(`CharacterMover.CheckFallDeath` が「残りHPぶんの攻撃」として同じ経路に乗る)と回復(`HealItem` が `CharacterStatusRuntime.Heal` を直接呼ぶためModelのHPは変わらない)。「奈落に落ちた」「アイテムを取った」の通知に分ける予定
