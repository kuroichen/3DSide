# キャラクターステータスの仕組み

HP・速度・攻撃力などの数値がどこで定義され、どう流れるかの解説。

## 二段構え: 定義(SO)と実行時の値(Entity)

```
CharacterStatus (ScriptableObject)  … マスターデータ。アセットとして編集する初期値
        ↓ 生成時に値をコピー
PlayerEntity / EnemyEntity          … 実行時の値(これが正)。CharacterEntity を継承
        ↓ ICharacterEntity として渡す(コピーではなく同じインスタンス)
CharacterMover                      … 移動速度・ジャンプ力・攻撃力・HPを読むだけ
```

| | 実行時の値 | 作る場所 | HPの計算・死亡判定 |
|---|---|---|---|
| プレイヤー | `PlayerEntity` | `StageLifetimeScope`(DIに1つ登録) | `PlayerModel`(下の「プレイヤーのHP」) |
| 敵 | `EnemyEntity` | `EnemyCharacter.Awake`(`defaultStatus` から) | `EnemyCharacter.TakeDamage` の中(敵にはPresenter/Modelがないため体が自分で行う) |

```csharp
// PlayerPresenter.CreatePlayer(生成直後)
this.playerView.SetEntity(this.playerModel.Entity);

// EnemyCharacter.Awake
this.enemyEntity = new EnemyEntity(this.defaultStatus);
SetEntity(this.enemyEntity);

// CharacterMover
protected override float Speed => this.entity?.Speed ?? 0.0f;  // 親のSplineMoverが移動計算で使うためoverrideが必要
public ICharacterEntity Entity => this.entity;                  // 接触した敵の攻撃力は enemy.Entity.Attack で読む
```

- 体は参照先を毎フレーム読むだけなので、Model側でEntityの値を変えれば(パワーアップ等)次のフレームから反映される。渡し直しは不要
- 体(`PlayerCharacter`)は `IPlayerEntity`(読み取り専用)としてHP・残機も読めるが、**HPを見て判断しない**。判断はModelに集める。必要になったら見せる範囲を絞ったインターフェースに分ける
- 以前の `CharacterStatusRuntime`(HP・攻撃力の実行時クラス)、`ILife` / `IAttack`、`ICharacterProperties` は、Entityへの一本化で削除した

### なぜ直接ScriptableObjectを書き換えないのか

1. **SOはアセット共有**: 同じ `CharacterStatus` を参照する敵が10体いたら、1体のHPを減らすと全員減る
2. **Editorでは変更が永続化する**: Play中にSOのフィールドを書き換えると、Play終了後もアセットに残る(初期HP3のはずが2で保存される事故)
3. リスポーンで初期値に戻したい → 敵はEntityを作り直す、プレイヤーは `PlayerModel.ResetHp()`

**「SOは読み取り専用、実行中の値はEntityへコピー」はUnity全般の定石**なので、新しいステータス項目もこの経路に乗せること(`CharacterStatus` → `ICharacterEntity` / `CharacterEntity` → 各Entityの作成箇所)。

### プレイヤーの性能値の3層(今後)

体が使う値は「① 基本値(SO) + ② 成長・進行(強化など。ゲーム全体で持続) + ③ ステージ中の状態(一時的なパワーアップ等)」の合成になる想定。今は①をコピーした③(`PlayerEntity`)だけがある。②を作るときはステージより上のScopeにModelを置き、`PlayerEntity` を作る箇所で足し込む。プレイヤー専用の設定(初期残機・無敵時間など)が増えたら `PlayerDefinition`(SO)への切り出しを検討する。

## 現在の定義値の場所

- アセット: `Assets/Data/` 配下(`Rail/CharacterStatus` メニューで作成)
- 項目: `hp` / `speed` / `jumpForce` / `attack` の4つ(`ICharacterEntity` の `Hp`・`MaxHp` / `Speed` / `JumpForce` / `Attack` に対応)
- ⚠ `jumpForce` は身長スケーリング(`scaleJumpByHeight`)有効時は使われない([レール移動系ナレッジ §4](レール移動系ナレッジ.md))

## プレイヤーのHP(PlayerModelが本体)

MVPへの移行で、プレイヤーのHP計算と死亡判定は `PlayerModel` に移した。`PlayerCharacter`(体)は「攻撃を受けた」と報告するだけで、HPを計算しない。

```
PlayerCharacter.TakeDamage ──OnAttackReceived(DamageInfo)──▶ PlayerView ──▶ PlayerEventBus
                                                                              │
PlayerPresenter.ApplyDamage ── PlayerModel.Damage(量) ──▶ DamageResult ◀─────┘
   ├ Ignored … 何もしない(死亡済み・ダメージ0。今後の無敵時間もここ)
   ├ Damaged … PlayerView.PlayHitReaction(attacker)(ノックバック+ダメージステート)
   └ Died    … PlayerView.Die() + PlayerEventBus.PublishDead()

PlayerCharacter.OnFellIntoPit ──InstantKillReceived──▶ PlayerView ──▶ PlayerEventBus ──▶ PlayerPresenter ── PlayerModel.Kill()
```

- 通知名は「出した時点で確定している事実」に合わせる。`AttackReceived` はHPに反映される**前**(Modelが受け付けない場合がある)。HPが減ったことはModelの `OnHpChangedObservable` で分かる
- 「死んだ(Dead)」はModelの判定を受けてPresenterが出す。「死亡アニメ終了(DeathAnimationFinished)」は体のアニメイベント(`OnDied`)由来なのでPlayerCharacterに残る
- プレイヤーは生成し直すたびに `PlayerModel.ResetHp()` で最大HPに戻す
- HUD(`StageHUDPresenter`)は `PlayerModel` のHP・残機の変化だけを見る。購読時に `StartWith(現在値)` で初期表示する
- 即死(奈落など): `CharacterMover.CheckFallDeath` → 仮想メソッド `OnFellIntoPit()`。敵は既定実装(`Entity.Hp` ぶんのダメージ)のまま、`PlayerCharacter` は上書きして `InstantKillReceived` を通知するだけ。`PlayerPresenter` が `PlayerModel.Kill()`(死亡済みならfalse)を呼び、死亡したら `Die()`(View.Die + PublishDead)。のけぞりは出さない。トゲ・溶岩なども同じ通知に流す想定
- 回復(アイテム): アイテムは効果のデータ(`ItemEffect`: 種類 `ItemEffectType` + 量)を持つだけで、HPを直接触らない。`ItemBase` がプレイヤーに触れると `IItemReceiver.ReceiveItem(effect)` を呼んで自分を消す(`First()` で1回だけ)。`PlayerCharacter` は `ItemReceived` を通知するだけで、`PlayerPresenter.ApplyItem` が種類に応じて `PlayerModel.Heal`(最大HPを超えない・死亡済みなら無効)などに振り分ける。効果を増やすときは `ItemEffectType` とこのswitchにケースを足す
