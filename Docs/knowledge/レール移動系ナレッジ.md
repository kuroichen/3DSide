# レール移動系ナレッジ(仕組み・調整・踏んだ罠)

[Spline移動リアーキテクチャ設計書.md](../specs/Spline移動リアーキテクチャ設計書.md)(基本設計)の続編。
実装を進める中で入った仕組みと、**なぜそうなっているか(=踏んだバグ)** をまとめる。
コードを読む前の地図として使う。

---

## 0. 大原則(これだけは覚えて帰る)

> **x/z はレールが決める。y は物理が決める。**

- キャラの水平位置は「今いるレールのどこか(railZ)」から計算される。自由な水平移動は存在しない
- 高さだけは重力・ジャンプの物理そのもの
- この原則から導かれる帰結:
  - ジャンプの横移動も「railZが進む」ことで起きる(だから端でrailZが止まると横移動も止まる)
  - レール同士の乗り換えは「位置が変わる」のではなく「参照するレールが変わる」
  - **レール座標(railZ)を決める計算も水平距離だけで行うべき**(罠⑤参照)

## 2. レール選択の仕組み

毎フレーム、`RailManager.World2Local` が全レールに「この位置、あなたの担当?」と聞いて回る。
各レール(`SplineRail.World2Local`)は **担当範囲内ならローカル座標(x,y,railZ)を、範囲外ならnullを返す**。

担当範囲 = 水平±2m(`maxHorizontalOffset`)、垂直±5m(`maxVerticalOffset`)、端の外±1m(`endMargin`)。

複数レールが名乗り出たときの優先順位:

```
① 「自分と同じ高さ〜下にあるレール」が「上にあるレール」に常に勝つ
② 同じクラス同士なら、オフセット距離が近い方
③ ほぼ同距離なら、端点の連結を考慮したヒステリシス(ShouldKeepCurrentRail)
```

①が肝(PlatformerRails方式)。これがあるから:

- 浮きレールの**下をくぐれる**(頭上のレールは candidate にならない)
- ジャンプで浮きレールの高さを超えた瞬間に**乗れる**(両方が「下」になり、近い方=浮きレールが勝つ)
- 浮きレールから**落ちれば自動で下のレールに戻る**(元レールが「上」になった瞬間に負ける)

つまりゲートなしで「ジャンプでルートを選ぶ」が成立する。図にすると:

```
      ＝＝＝＝＝ 上レール
        ↑ジャンプでこの高さを超えると上レールが勝つ
   ●
＿＿＿＿＿＿＿＿ 下レール ←地上にいる限りこちらが勝ち続ける
```

## 3. レール端の仕組み(余白まわり)

端に関わる値は3つ。役割が違う:

| 値 | 場所 | 意味 |
|---|---|---|
| `endMargin` (1m) | SplineRail | レールが「担当」を名乗れる端の外の範囲。かつ地上での歩き出し限界 |
| `airborneEndMargin` (5m) | SplineMover | **空中でだけ**許される端の外の距離。ジャンプの弾道が端で死なないため |
| 引き戻さないクランプ | SplineMover | 既に範囲外にいるとき、接地して余白が縮んでも現在位置より内側へ強制しない |

動きの例(端からのジャンプ飛び移り):

```
① 端に向かって走りながらジャンプ
② railZ が端を越えて伸びる(空中なので5mまで)
   → 位置は端の接線方向に直線外挿 = 弾道がそのまま続く
③ 1mを超えた時点で元レールは「担当」を名乗れなくなる
④ 下や先にあるレールが名乗り出て乗り換え(§2のルール)
⑤ 着地。もし誰も拾わなければ落下死(fallDeathY)
```

**注意**: レールが地形をカバーしていない場所に着地すると、前方に見えない壁ができる
(接地中は範囲外へ進めないため)。ステージは「歩ける場所には必ずレールがある」前提で作ること。

## 4. ジャンプシステム

### 数値の由来

レトロアクションの映像解析値(30fpsフレーム単位: 初速26 / 上昇重力2 / 下降重力3)を秒に換算したもの。
特徴は**非対称重力**: 上昇(-36)より下降(-54)が1.5倍強い。「ふわっと上がってストンと落ちる」の正体。

### 身長スケーリング(scaleJumpByHeight)

重力・初速を直接持たず、**「身長の何倍を・何秒で跳ぶか」から導出**する:

```
高さH = jumpHeightInBodies × CharacterController.height
上昇重力 = -2H / timeToApex²
初速     =  2H / timeToApex
下降重力 = 上昇重力 × fallGravityRatio
```

→ モデルの頭身を変えてCC.heightを合わせれば、**時間(手触り)を保ったまま飛距離だけ身の丈に縮む**。

⚠ ONの間、`CharacterStatus.jumpForce` とインスペクタの gravityUp/Down は**無視される**(要整理のバックログ)。

### 手触り4点セット(全部ジャンル標準の相場値)

| 機能 | 値 | 効果 |
|---|---|---|
| 可変ジャンプ | 離した瞬間 上昇×0.4 | ちょん押しで小ジャンプ(高さ比 約1:4) |
| コヨーテタイム | 0.1秒 | 崖を離れた直後でも跳べる |
| ジャンプバッファ | 0.15秒 | 着地前の先行入力が着地瞬間に発火 |
| 終端速度 | 20m/s | 長い落下でも制御を失わない |

発火条件は「バッファ生存 かつ コヨーテ生存 かつ 硬直中でない」の一本(コードパスが1つなので追いやすい)。

### 着地3種

| 種類 | 条件 | 挙動 |
|---|---|---|
| 走り抜け着地 | 移動中・落下4m未満 | 着地モーションなし。ノンストップ |
| 静止着地 | 入力なし・落下4m未満 | Landモーション。入力/ジャンプで即キャンセル可 |
| ハード着地 | **落下距離4m以上**(空中の最高到達点から計測) | Land+0.25秒の入力ロック。高所から降りるコスト |

判定を落下「速度」でなく「距離」にしているのは、終端速度のせいで高所落下の速度差が潰れるため。

## 5. 踏んだ罠と対策(ナレッジの核)

| # | 症状 | 真因 | 対策(現在の実装) |
|---|---|---|---|
| ① | 浮きレールに入れるが出られない(檻) | 水平移動がレール駆動なので、端でrailZが止まると空中でも横に動けない | 端の余白+「下にあるレール優先」ルール(§2①) |
| ② | 乗り換えの瞬間ワープする | 端の延長線上では接線方向のズレがオフセットに数えられず、遠くから吸い付いていた | はみ出し量をrailZに反映し、余白超えは担当拒否 |
| ③ | 頭が足場に引っかかる | ジャンプ放物線と被さる床の物理的干渉 | レベルデザイン側で解決(同高ギャップ跳び→のち多層は互い違い配置)。すり抜け床は限定利用 |
| ④ | ジャンプ中に端で横移動が止まる | 端のクランプが空中でも1mのまま | 空中は余白5mに拡張(§3) |
| ⑤ | 落下中に左へ引き戻されるループ | **最近傍点を3D距離で選んでいた**。坂の上空では斜め後ろ上の点が「最近傍」になる | 水平距離(XZ)最小のrailZへ絞り込む三分探索(大原則への回帰) |
| ⑥ | 端の角で移動/落下モーションが無限往復 | CCのisGroundedはカプセル縁が角にかすると true→接地扱い→落下速度リセット→永遠に滑り落ちない | 接地=「CC接触 かつ 中心直下のSphereCast」のAND条件 |
| ⑦ | カーブ区間でガクつく・速度が揺れる | Splineのtは弧長に比例しない(t×全長の近似が崩れる) | ConvertIndexUnitで距離⇔t を正確に変換 |

**教訓**: ②⑤⑦は全部「レール座標の計算が大原則(x/zはレール、yは物理)からズレていた」ことが根っこ。
新しい挙動を足すときは、まず大原則に照らして考える。

## 6. 調整パラメータ早見表

| 触りたいもの | 場所 | パラメータ |
|---|---|---|
| ジャンプの高さ | CharacterMover | `jumpHeightInBodies`(身長比) |
| ジャンプのキレ(時間) | CharacterMover | `timeToApex`(上昇秒数)。高さ据え置きで時間だけ変わる |
| 落下の重さ | CharacterMover | `fallGravityRatio`(下降/上昇の比。上げるとキレ増) |
| ちょん押しの効き | CharacterMover | `jumpCutMultiplier` |
| 操作の吸い付き感 | CharacterMover | `coyoteTime` / `jumpBufferTime` |
| ハード着地の閾値・硬直 | CharacterMover | `hardLandFallDistance` / `hardLandStunTime` |
| 端から歩き出せる距離 | SplineRail | `endMargin`(0で昔のカチッとした端に戻る) |
| ジャンプで端を越えられる距離 | SplineMover | `airborneEndMargin` |
| レールの捕捉範囲 | SplineRail | `maxHorizontalOffset` / `maxVerticalOffset` |
| 乗り換え時の追従速度 | CharacterMover | `railCorrectionSpeed`(下げるとヌルッと、上げるとキビッと) |

**スケールの経験則**: ジャンプ性能を変えたら、ステージの高低差・ギャップ幅・道幅・カメラ距離も
同じ感覚で追従させること(要求値はジャンプ限界の6〜7割が1面の相場)。
性能の実測は JumpGym シーン(Tools → Rail → Create Jump Gym)で。

## 7. 既知の制約・バックログ

- **レール未カバー地帯に着地すると前方に見えない壁**(§3注意書き)。余白設計を「クランプ」から「担当範囲」ベースに整理する時に根治予定
- **天井判定は旧式**(CollisionFlags.Aboveの生値)。角かすりでジャンプが殺される可能性(接地側と同じSphereCast化が対策)
- レールのtransformスケールは**(1,1,1)前提**(ConvertIndexUnitがローカル長、Lengthがワールド長のため)
- 曲率半径3m未満のヘアピンでは水平最近傍の探索が誤収束し得る(現行ステージの緩いカーブは対象外)
- 敵の重力は現状プレイヤーと同条件(意図的)。将来は敵データのenumで重力パターンを選ぶ構想
- ゲームオーバー処理が未実装(残機0で死ぬと`OnGameOver`通知は出るが誰も聞いていない)
