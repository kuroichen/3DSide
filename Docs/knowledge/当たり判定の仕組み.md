# 当たり判定の仕組み

「誰が・何に・どう当たるか」の全体設計。
OnTriggerEnterが発動する条件の一般知識は [learning/05](../learning/05_TriggerEnterの発動条件.md) を参照。

## 設計方針: 物理とロジックを分ける

| 役割 | 使うもの | 例 |
|---|---|---|
| 物理的な衝突(地形に立つ・壁に阻まれる) | CharacterController + CapsuleCast | 接地、壁 |
| ゲームロジックの判定(ダメージ・取得・通過) | **Trigger Collider** + `CollisionObserver` | 被弾、武器、アイテム、エリア |

物理判定はレイヤーで絞る(壁チェックはTerrain/Gimmickのみ)。ロジック判定はTriggerなので物理に干渉しない。

## レイヤー構成

| レイヤー | 用途 |
|---|---|
| Player | プレイヤーの被弾判定・アイテム取得判定 |
| Enemy | 敵の判定(プレイヤー武器の攻撃対象) |
| Terrain / Gimmick | 地形。壁CapsuleCastの対象 |
| Gate | レール強制切替ゲート(Raycast判定) |

受信側はレイヤーでフィルタする:

```csharp
.Where(col => col.gameObject.layer == LayerMask.NameToLayer("Enemy"))
```

## CollisionObserver — 判定の共通部品

`OnTriggerEnter` / `OnCollisionEnter` をUniRxのObservableに変換するだけの薄いコンポーネント。

- **Colliderと同じGameObjectに付ける**(Unityのイベントは子Colliderから親へ伝播しないため。Awakeで警告あり)
- `SetCollisionEnabled(bool)` でCollider自体をon/offできる(攻撃ウィンドウに使用)
- 購読側は `.Where` でレイヤーを絞り、`GetComponentInParent` で相手の本体スクリプトを取る(当たったのは相手の子Colliderかもしれないため)

## プレイヤーの判定は3つある

```
Player GameObject
├── CharacterController      … 物理(地形との衝突)。ロジック判定には使わない
├── 被弾Trigger + Observer   … Enemyレイヤーに触れたらTakeDamage
└── 武器Trigger + Observer   … 通常は無効。攻撃中だけ有効
```

### ダメージが通る流れ(プレイヤー → 敵)

```
攻撃入力 → PlayerState.Attack → AttackTriggerでアニメ再生
  → アニメイベント OnAttackStart → 武器Collider有効化
      → 敵TriggerにEnter発火
          → col.GetComponentInParent<IDamageable>().TakeDamage(DamageInfo)
              → EnemyCharacter: ノックバック + HP減算 → Damage/Deadステートへ
  → アニメイベント OnAttackEnd → 武器Collider無効化、Moveステートへ
```

- 攻撃判定の有効期間を**アニメーションイベント**で制御するのが肝。「振りかぶり中は当たらない、振り抜きだけ当たる」がアニメと自動で同期する
- Colliderごと無効化しているので、1回の攻撃で同じ敵に多段ヒットしない(Enterは1接触1回)

### 接触ダメージの流れ(敵 → プレイヤー)

```
被弾TriggerにEnemyレイヤーがEnter
  → enemy.Entity.Attack からダメージ量を取得
  → PlayerCharacter.TakeDamage(DamageInfo{ attacker, damage })
      → AttackReceived を通知するだけ(HPは計算しない)
        → PlayerPresenter → PlayerModel.Damage → DamageResult
            Damaged … PlayHitReaction(ノックバック → Damageステート)
            Died    … Die(Deadステート)
```

プレイヤーのHP計算はPlayerModelが行う([キャラクターステータスの仕組み](キャラクターステータスの仕組み.md))。敵は `EnemyCharacter.TakeDamage` の中でHP減算 → ノックバック → Damage/Deadステートまで自分で行う。


## DamageInfo と IDamageable — 攻守の契約

```csharp
public struct DamageInfo { public Transform attacker; public int damage; }
public interface IDamageable { void TakeDamage(DamageInfo damageInfo); }
```

- 攻撃側は相手が誰か知らなくてよい。`IDamageable` さえ取れれば `TakeDamage` を呼ぶだけ
- `attacker` のTransformを渡すのは**ノックバック方向の計算**のため([ノックバックの仕組み.md](ノックバックの仕組み.md))

## アイテム・エリアイベントも同じパターン

- `ItemBase`: PlayerレイヤーのEnterを購読 → `GetComponentInParent<IItemReceiver>` → `ReceiveItem(効果)` で渡すだけ → Destroy。効果の適用はPlayerModel側([キャラクターステータスの仕組み](キャラクターステータスの仕組み.md))
- `AreaTrigger`: プレイヤーの通過でエリア遷移/チェックポイント/ゴールのイベントを発火

**新しい「触れたら何か起きるもの」を作るときは、Trigger Collider + CollisionObserver + レイヤーフィルタ + GetComponentInParent の4点セットを踏襲すること。**
