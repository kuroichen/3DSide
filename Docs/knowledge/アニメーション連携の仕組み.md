# アニメーション連携の仕組み

「アニメーションのこの瞬間にロジックを動かしたい」(攻撃判定の有効化、死亡演出の完了待ちなど)を
どう実現しているかの解説。部品は `AnimationEventObserver` と `AnimationStateObserver` の2つ。

## 方針: AnimatorからロジックへはObservableで通知

Animator(見た目)とゲームロジックを直接結合させず、Observer部品がUnityのコールバックを
UniRxのObservableに変換して仲介する。当たり判定の `CollisionObserver` と同じ発想。

## AnimationEventObserver — 「この瞬間」の通知

AnimationClipに打った**Animation Event**を受け取る部品。

```
AnimationClip上にイベントを打つ(関数名: OnAnimationEvent、String引数: イベント名)
  → Animatorと同じGameObjectのAnimationEventObserverが受信
    → OnAnimationEventObservable() にイベント名(string)が流れる
      → 購読側が .Where(name => name == "OnAttackStart") で選別
```

**全イベントで同じ関数 `OnAnimationEvent(string)` を使い、イベント名で区別する**のがルール。
クリップごとに専用メソッドを増やさない(受信側のメソッドが無いとUnityが警告を出すため、種類が増えるほど管理が破綻する)。

### 現在使われているイベント名

| イベント名 | 打つ場所 | 用途 |
|---|---|---|
| `OnAttackStart` | 攻撃モーションの振り始め | 武器Colliderを有効化([当たり判定](当たり判定の仕組み.md)) |
| `OnAttackEnd` | 攻撃モーションの振り終わり | 武器Collider無効化 + Moveステートへ復帰 |
| `OnDied` | 死亡モーションの最終フレーム | 「演出まで含めて死亡完了」の通知。リスポーン開始の合図([ステージ進行](ステージ進行の仕組み.md)) |

新しいイベント名を追加するときはこの表も更新すること。**文字列なのでtypoしても実行時まで気づけない**。

### なぜタイマーではなくAnimation Eventか

「攻撃開始から0.2秒後に判定ON」のようなタイマー方式だと、モーションを差し替え・速度変更するたびに
数値を合わせ直すことになる。イベントはクリップに埋まっているので、**モーションを変えても同期がズレない**。

## AnimationStateObserver — 「今どのステートか」の通知

Animator Controllerのステート遷移(Enter/Exit)をObservable化する部品。

- コールバック(StateMachineBehaviour)ではなく、**毎フレーム `GetCurrentAnimatorStateInfo` をポーリング**してステートのhashが変わったら通知する方式
- `IsInTransition` 中はスキップ(遷移中の中間状態を誤検知しない)
- 通知は `shortNameHash`(int)。比較する側は `Animator.StringToHash("StateName")` で照合する

StateMachineBehaviour方式(Animator側にスクリプトを挿す)を避けたのは、ロジックがAnimator資産の中に
散らばるのを防ぐため。Observerなら通知の受け口がシーン側に揃う。

## Animatorパラメータの一覧(ロジック→アニメ方向)

逆方向(ロジックからアニメを動かす)は通常のAnimatorパラメータで行う:

| パラメータ | 型 | 設定箇所 |
|---|---|---|
| `Speed` | Float | SplineMover(移動入力の絶対値) |
| `IsGrounded` | Bool | CharacterMover(接地判定) |
| `VerticalVelocity` | Float | CharacterMover(昇降の速度。ジャンプ↔落下のブレンド用) |
| `HardLand` | Bool | CharacterMover(ハード着地かどうか) |
| `JumpTrigger` / `AttackTrigger` / `DeadTrigger` | Trigger | 各アクションの開始 |

**まとめ**: ロジック→アニメは「パラメータ」、アニメ→ロジックは「Animation Event + Observer」。
双方向を分けておくことで、どちらから追っても流れが一方通行で読める。
