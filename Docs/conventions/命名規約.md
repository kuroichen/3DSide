# 命名規約

## Manager系クラスの使い分け(2026-07-25合意)

| 接尾辞 | 責務 | 例 |
|---|---|---|
| **〜FlowManager** | インゲームの「進行」。状態遷移を持ち、時間軸に沿ってゲームを進める | `StageFlowManager`(ステージ内進行)、`GameFlowManager`(シーンをまたぐ全体進行・新設予定) |
| **〜Manager** | 常駐サービスやリソースのライフサイクル管理。進行状態を持たない | `AudioManager`、`PlayerManager`、`RailManager` |

### 狙い

- 「GameManager」のような何でも屋クラスへの肥大化を防ぐ
- 機能追加時の置き場所を名前で縛る:「進行(いつ何が起きるか)の話か、資源(何をどう保持するか)の話か」で判断する
  - 例: ポーズ=進行 → GameFlowManager側、スコア保持=資源 → 別Manager

## キャラクター本体は「〜Character」(2026-10-11合意)

移動・ジャンプ・物理・ステートマシン・アニメーション連携・攻撃判定を持つ、キャラクターの「体」となるMonoBehaviourは `〜Character` と名付ける。

| クラス | 役割 |
|---|---|
| `PlayerCharacter` | プレイヤーの体(旧 `PlayerController`) |
| `EnemyCharacter` | 敵の体(旧 `EnemyController`) |
| `CharacterMover` | 両者の共通基盤(レール移動・重力・被ダメージの受け口) |

- **`〜Controller` は使わない**。入力はIPlayerInputSourceとして外から渡しており「入力を受けて操作する」役割ではないこと、Unity標準の `CharacterController` と同じPrefabに並んで紛らわしいこと、MVPの用語(MVCのController)と混同されやすいことが理由
- Unreal Engineの用語(体=Character、入力=PlayerController)と同じ分け方。このプロジェクトで入力側に相当するのは `PlayerInputSource`
- Presenterとの窓口は `〜View`(例: `PlayerView`)。Presenterは `〜Character` の中身を直接知らない
